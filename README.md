# 遗链 EstateLink · 客户档案、核验与行情演示

在原客户池与行情 Demo 上增加场景二：**客户与主游戏账号录入 → SQLite 自动保存 → 多项资产及合同登记 → 手机端脱敏展示**。

使用 Python 标准库 HTTP 服务、SQLite、原生 HTML/CSS/JavaScript；加密依赖 `cryptography`。无需 Node.js 构建前端。

## 首次运行（Windows PowerShell）

在项目目录运行，需 Python 3.10 或以上：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt

# 显式执行一次，生成本次演示数据库的密钥。不要公开密钥。
$env:ESTATELINK_DATA_KEY = (& .venv/Scripts/python.exe generate_key.py).Trim()
$env:AUTO_INTERVAL = '999999'
.venv/Scripts/python.exe demo/server.py
```

**密钥必须与数据库一起妥善保管。** 上面的变量只在当前 PowerShell 及其子进程有效；关闭该终端前，请通过自己的密码管理器安全保存密钥。以后在新终端将同一个密钥重新设置到 `ESTATELINK_DATA_KEY`，再启动服务。不要对已有数据库重新生成密钥。

服务不会自动生成、替换密钥，也不自动加载 `.env`。缺少密钥、密钥错误或密文损坏时停止启动，不重置资料。数据库默认位于 `demo/estatelink.sqlite3`；可通过 `ESTATELINK_DB_PATH` 指定其他位置。密钥、数据库及 SQLite 附属文件均在 Git 忽略范围内。

## 场景二演示

1. 客户池点击“添加用户”，填写虚构姓名、`100` 开头的 11 位演示手机号、游戏及账号；证件等可选。
2. 创建后进入该客户档案，登记两项资产，填写数量、取得总成本、处置意愿。
3. 登记合同编号、名称、状态及日期。合同状态只是人工登记，不表示平台验证或完成签署。
4. 点击“手机端档案预览”，在“账号信息”查看脱敏资料、资产及合同。
5. 后台修改资产数量，手机端手动刷新或等待至多约 5 秒。
6. 停止服务，并在**保留相同密钥的终端**重新启动；记录应仍存在。

所有变更自动保存，不需要点击保存按钮。客户池的“自动保存状态”只保留兼容提示。

每位客户一个主账号，可登记多项资产；无删除接口。账号整体与道具单卖是不同方案，金额不相加。新登记资产显示“暂无行情”，不会套用别人的报价；原两位客户的模拟行情和处置流程继续可用。

## 数据保护与演示边界

- **只使用虚构资料。演示身份，不代表真实访问授权。** 本地 Demo 没有登录或客户间访问隔离，知道 ID 的本机调用者可以访问脱敏档案和写接口。
- 姓名、电话、证件、邮箱、地址、紧急联系人及账号标识由 Fernet 加密存储；身份证重复检测使用独立派生密钥的 HMAC 指纹。
- 列表、详情及行情 API 在服务器生成脱敏数据。编辑敏感字段时留空表示保持原值，勾选“清除此项”删除可选信息。
- 游戏密码不录入、不保存、不返回。短信核验和身份状态为原有演示逻辑，并非真实死亡事实或继承资格认定。
- 合同只保存元数据；行情、手续费、买家意向和交易均为模拟。不连接真实短信、交易或支付。
- 备注、合同名称和短信正文属于自由文本，请勿在其中填写真实个人资料。

## 自动迁移

首次启动建立数据库，优先读取旧 `demo/data.json`；没有时导入原来的 12 位虚构客户。保留客户 ID、状态及未回应次数，为每位客户建立主账号，并导入两例道具和固定行情关联。已有 `market_state.json` 的处置进度也会迁移；否则保留原默认演示进度。

导入成功后以 SQLite 为唯一运行数据源，核验记录和处置状态也持久化。重启不重复导入，不再写旧 JSON。存在而损坏的旧文件会使启动失败，已写记录回滚。

**旧 JSON 保留原样，可能仍包含旧明文占位资料和密码字段。** 这不代表运行数据库仍保存密码。旧文件不会通过静态路由公开，不要把包含真实信息的旧文件提交到 Git。
