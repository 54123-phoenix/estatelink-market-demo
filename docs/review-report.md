## 数据正确性问题与关闭结果

### P2：成本输入采用科学计数法时写入错误金额

位置：`demo/views/archive-admin.js:85`。

成本控件是 type=number，浏览器允许 `1.25e2` 这样的有效数值；原处理直接按小数点切分，把它转换成 2600 分，正确值应为 12500 分。这会成功写入错误的总成本。用实际 submit 回调的 Node VM 定向重现，观察到发送体 costMinor=2600。

已关闭：现在以正则限制普通十进制、最多两位小数，并检查 Number.isSafeInteger。对实际提交回调复验，科学计数法和超出安全范围的金额均未发出写请求，`125.00` 正确转换成 12500 分；校验异常进入原错误反馈路径，保留输入。

### P2：编辑其他资产字段会替已清空的处置意愿写入默认值

位置：`demo/views/archive-admin.js:45`。

后端和规格允许可选字段清除，`disposition:null` 是有效状态。原处置意愿 select 没有空选项；打开这种资产时浏览器自动选择第一项 inherit，之后仅编辑备注并保存，也会将处置意愿改为继承。

已关闭：现在有明确的未填写选项，并将空值发送为 null。复验实际 editAsset 输出为空选项 selected，实际提交体 disposition 保持 null。

## 已发现并修复的问题

- P2：原 saveForm 只禁用当前表单按钮，保存请求未完成时仍可用外部编辑/新增按钮重开同一表单；旧响应会隐藏新编辑。定向 VM 重现得到新表单在旧请求完成前可见、完成后被隐藏。当前实现已在构造 FormData 后禁用档案区按钮和输入，并恢复原禁用状态。
- P2：原币种 select 仅提供 CNY/USD/EUR/HKD，API 允许的 GBP 等币种编辑时会自动变成 CNY。当前已改为保留原值的三字母文本输入。
- P2：道具 game 是可选字段，原表单却要求填写，导致合法的无游戏道具无法单独编辑备注。当前已改为仅主账号要求 game。
